# 휴가 변경·취소 동기화

`sync/index.js`의 10분 동기화는 회사 `1600`의 한국시간 기준 어제부터 7일 후까지 승인 휴가를 읽고 운영 DB와 대조한다. 별도 연차 작업자와 수동 동기화 API도 같은 기간과 `src/lib/leaveReconciliation.cjs`를 사용한다. 직원별 과거 이력 백필만 `fullHistory: true`로 전체 이력을 읽는다.

- 원본 승인 상태(`40`)가 있는 휴가는 사번·시작일·휴가코드로 대조해 신규 등록 또는 변경한다.
- 원본과 운영 DB에 동일한 기간 겹침 조건(`종료일 >= 어제`, `시작일 <= 7일 후`)을 적용한다. 경계일을 포함하며 여러 날에 걸친 휴가는 원래 전체 기간을 보존한다. 범위 밖 기존 기록은 변경하지 않는다.
- 이 범위의 원본 승인 집합에서 빠진 기존 승인 건은 `CANCELLED`로 보존한다. 날짜나 휴가종류를 바꾼 경우에는 대조 범위에 해당하는 이전 건을 취소하고 새 건을 반영한다. 범위 밖에서 일어난 과거 변경·취소는 주기 대조에 반영되지 않으며 별도 과거 백필이 필요하다.
- 기존 DB에서 `status`가 5자로 제한된 경우 먼저 `ALTER TABLE public.sa_leaves ALTER COLUMN status TYPE varchar(20);`을 적용해야 취소 상태를 저장할 수 있다.
- 취소 후 재승인된 건은 다시 `40`으로 바뀐다. 값이 같은 건은 재저장하지 않는다.
- 조회 성공 시 승인 휴가가 0건이어도 기존 승인 건을 취소 처리한다. 원본 직원 범위가 비었거나 원본 조회·운영 DB 전체 페이지 조회·데이터 검증이 실패하면 휴가 쓰기를 시작하지 않는다.
- 다른 회사와 직원별 백필 범위 밖의 데이터는 대조 대상에 넣지 않는다. 승인 저장에 실패하면 그 회차의 취소 처리는 시작하지 않는다. 여러 배치 중 쓰기가 실패한 경우 다음 회차의 대조 기간에 속한 건을 재시도한다.
- 원본에서 동일 키의 승인 건이 서로 다른 값으로 중복되면 임의 선택하지 않고 오류로 중단한다.

부서 캘린더는 승인 건만 표시하며 취소 이력의 날짜까지 조회해 오래된 취소 일정도 정리한다. 프로필 상태는 취소된 휴가와 일치하는 현재·예약 상태를 정리한다. 외부 상태 정리에 실패하면 취소 이력을 다음 회차에도 전달해 재시도한다.

서버 PC 업데이트 후에는 처음 실행부터 해당 기간 대조가 진행된다. 로그의 `휴가 대조 완료`에 대조 기간과 승인·추가/변경·취소·동일 건수가 남는다. 서버 PC의 MySQL 원본과 연결한 실제 검증은 별도로 필요하다.
